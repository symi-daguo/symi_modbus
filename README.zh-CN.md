# Symi Modbus

<img src="custom_components/symi_modbus/brand/logo.png" alt="Symi Modbus" height="96" align="right">

[English](README.md) | [中文](README.zh-CN.md)

**Symi Modbus 继电器模块**与**Symi 墙面板**的 Home Assistant 集成，支持串口 RTU 与 TCP。

一个配置条目描述**一条 Modbus 主线**（一个串口或一个 TCP 端点）。属于它的东西都是**子条目**，
可以单独添加、修改和删除：各台从站、各条面板总线，以及面板按键与继电器之间的关联。

| | |
|---|---|
| 版本 | **2.6.4** |
| Home Assistant | **2025.3.0** 及以上 |
| 依赖 | `pyserial`、`pyserial-asyncio-fast` |

## 特点

- **串口 RTU 与 TCP**，帧格式按连接方式选择。
- **一条主线挂多台从站**——每台从站是独立设备，每个线圈一个开关。
- **墙面板**——面板上的每个按键都是一个开关，指示灯由集成驱动。
- **按键关联**——面板按键驱动继电器，继电器点亮面板指示灯，**状态双向同步**。
- **指示灯用面板自己的码驱动**——这些码由集成从面板上报的帧里学出来。
- **配置可以导出、可以导入**，也会跟着 Home Assistant 的备份一起走。
- **日志安静**——掉线只报一次，不是每轮轮询都报。

## 安装

**HACS**——把 `https://github.com/symi-daguo/symi_modbus` 添加为「集成」类型的自定义仓库，
安装后重启 Home Assistant。

**手动安装**——把 `custom_components/symi_modbus` 复制到配置目录的 `custom_components` 下，重启。

Docker 需要把串口映射进容器：

```yaml
devices:
  - /dev/ttyUSB0:/dev/ttyUSB0
```

## 快速上手

全部操作都在**设置 → 设备与服务**里完成。

**1. 主线。** *添加集成 → Symi Modbus* 打开配置流程。选**串口**或 **TCP**，填好线路参数并确认
第一台从站。建出来的条目就是主线，它持有与总线的连接。

**2. 从站。** 在条目页面点**添加从站**，填设备地址、起始线圈和线圈数量。每台从站是独立设备，
每个线圈一个开关。

**3. 面板与关联。** **添加面板总线**填面板所在线路：品牌、串口、波特率和线上面板的地址。
**添加按键关联**把面板按键和从站继电器连起来。

每一部分都能**单独修改或删除**，改动只影响它自己。手工改过的名字会保留。

## 设置项

| 设置项 | 在哪里 | 含义 |
|--------|--------|------|
| 扫描间隔 | 主线的选项 | 对所有从站跑完一轮的时间。默认一秒，允许半秒。 |
| 波特率、数据位、校验位、停止位 | 主线、面板总线 | 线路参数。默认 9600、8 位、无校验、1 位停止。 |
| 从站地址 | 从站 | 设备的单元号，10 就是 `0x0A`。 |
| 起始线圈、线圈数量 | 从站 | 设备实际有的线圈。32 路模块填 32。 |
| 面板地址、面板数量 | 面板总线 | 这条线上面板的地址。 |
| 每面板按键数 | 面板总线 | 该品牌的面板有几个按键。 |
| 高级设置 | 面板总线 | 指示灯用的帧和灯的码。只有灯不听话时才需要动。 |
| 模式 | 按键关联 | **开关**（默认）保持继电器状态，**场景**只触发一次。 |

### 面板的指示灯

面板上报状态时用的码可能是它自己的一套，协议文档只写了开是 `0x01`、关是 `0x00`。所以集成会从
面板发来的帧里**学出每个面板的码**，并跟实体存在一起，于是灯是用面板听得懂的码驱动的。

日志会告诉你学到了什么：

```
Panel 1 button 1 uses the code 17 for on
Panel 1 button 1 uses the code 16 for off
```

按两下按钮，一次开一次关，面板的两个码就都学会了。面板完全不上报状态时，可以在面板总线的
**高级设置**里手填。

**灯的码和关联的模式没有关系。** 模式属于「按键↔继电器」这条关联，码属于面板总线。

### 关联的两种模式

| 模式 | 继电器的行为 | 面板指示灯 |
|------|--------------|------------|
| **开关**（默认） | 保持状态，继电器的状态就是灯的状态。 | 跟着继电器走。 |
| **场景** | 只触发一次，比如智能家居的某个场景。 | 回应这次按键并保持自己的状态，继电器回落也不会把它熄灭。 |

### 面板总线和主线不共用一个串口

主线是「发请求、等回答」，面板是「自己上报」，两者混在一个口上会互相干扰。**但两条面板总线可以
共用一个串口**——一条 RS485 上可以挂同品牌的多块面板，每一帧都带着自己面板的地址。

## 备份、导出与导入

配置是 **Home Assistant 备份**的一部分，恢复备份就能把集成原样带回来。

如果只想搬这个集成，配置还可以导出成文本再导回来。两者都在主线的**配置（齿轮）**按钮里：

| 步骤 | 做什么 |
|------|--------|
| **导出配置** | 把主线、从站、面板总线和关联写成 YAML 放进一个文本框。 |
| **导入配置** | 把 YAML 读回来，主线里不在文本中的部分会被移除。 |

关联写的是「它属于哪块面板、哪个线圈」，不是实体 id，所以文本读得懂，换台机器串口名字不一样
关联照样对得上。导入前可以先改文本。

## 排查问题

**面板的灯不跟着继电器走。** 日志会告诉你面板用的哪个码、出去的是哪种帧。只认设置帧 `0x03` 的
面板，需要在**高级设置**里改**指示灯反馈帧**。

**面板总线不通。** 日志会说明原因：

```
The panel bus /dev/ttyS2 cannot be opened: Could not configure port: (5, 'I/O error')
```

被别的程序占着的串口会被拒绝，因为字节会被两边瓜分。

**想看总线上的原始数据。** 集成页面有一个**下载诊断**按钮，下载到的文件里有主线和每条面板线路
上最近几帧的十六进制数据，还有学到的码。日志不会因此变吵，数据要的时候才在。

## 开发

```bash
docker run --rm -v "$PWD:/work" -w /work homeassistant/home-assistant:stable \
  sh -c "pip install pytest-asyncio -q && python -m pytest tests/ -q --asyncio-mode=auto"
```

- `tests/` 覆盖帧编解码、主线行为、面板协议、关联和配置。
- `scripts/modbus_simulator.py` 在 TCP 端口或伪终端上模拟一台 Modbus 从站。
- `scripts/verify_load.py` 用模拟总线压测主线，报告每轮耗时、各从站的可用性和内存增长。
- `scripts/make_release.py` 打包发布用的压缩包。
- `scripts/generate_brand.py` 从 `assets/icon_source.png` 重新生成品牌图片。

## 更新日志

### 2.6.4

- 按键的**状态按面板品牌的读法来判**，不再靠翻转实体的状态。实体可能因为继电器写过灯而不同步，
  面板用的码就会学到错误的状态上去：用码 0 表示「关」的面板，会被当成用码 0 表示「开」。
- **手填的码最可信**，优先于学到的码。
- **LF 面板的按键恢复翻转**。LF 的帧里不带状态，第一次按下学到的码把翻转盖住了。

### 2.6.3

- **在总线上被损坏的帧会被丢掉**。两块面板同时上报，或者面板上报时我们正好在发帧，它们会互相
  损坏，而被损坏那一帧的地址字节属于另一块面板。以前这种帧会被当成这块面板的按键，于是另一块
  面板的按键能带动这一块的指示灯。

### 2.6.2

- 按键的**码在已知时就直接决定状态**，不再靠翻转。翻转会把码学到错误的状态上去（只要继电器写过
  灯就会发生），面板用码 0 表示状态时现在也能认出来，两个分不开的码不再被使用。
- **回显改用码来辨认**，不再用开/关。面板用自己的一套码表示状态时，回显会被当成按键，批量开关
  一批按键时就会误写继电器。
- 面板**可能还在发数据时不写**，集成的帧与面板的报文不再在总线上互相损坏。

### 2.6.1

- **场景每次按下都会被触发**。面板的按键是切换型的，跟着它的状态走，第二次按下就会把继电器关掉，
  场景也就不会触发。
- 面板现在最多可以有 **32 个按键**。面板用 channel 给按键编号，驱动场景的按键编号比驱动灯的按键
  高，所以面板上报的 channel 可能远大于八。
- 面板**上报了没有实体的按键**时，日志会说明，并把面板总线该设成多少个按键写清楚。

### 2.6.0

- **两条面板总线可以共用一个串口**。一条 RS485 上可以挂同品牌的多块面板，每一帧都带着自己面板
  的地址，所以一个连接读一条线，字节不会被瓜分。
- **诊断**里有总线的原始数据：主线和每条面板线路上最近几帧，以及面板用的码。在集成页面下载，
  日志不会变吵。
- 文档**更短了**，并且有**中英两份**。

### 2.5.0

- **配置可以导出、可以导入**（文本）。关联写的是它属于哪些设备，所以换台机器串口名字不一样也
  照样对得上。
- 配置是 **Home Assistant 备份**的一部分。
- 指示灯的**设置收进「高级设置」**折叠区。
- 主线的**选项有了菜单**：轮询间隔、导出、导入。
- **面板的码又能存住了**。之前写用的接口 Home Assistant 并没有，每次重启都会丢。
- 面板总线**只有串口真的打开了才算 ready**，打不开会说原因。
- **诊断**里带着总线的原始数据。

### 2.4.2

- 指示灯的码说明了留白是什么意思。
- 通过 HACS 安装重新跟随仓库的发布标签。

### 2.4.1

- **继电器一变，指示灯就重新写一次**，哪怕面板实体已经显示成想要的样子。
- **写线圈**降到 debug 级别。

### 2.4.0

- **关联知道自己驱动的是开关还是场景**。
- **按面板键时立刻点亮自己的指示灯**。

### 2.3.1

- **面板上报状态用的码**现在会学，按键分别学，并跟实体存在一起。

### 2.3.0

- 面板指示灯按协议文档要求的**上报帧 `0x04`** 驱动，**按键的地址**也改成逐个学。

### 2.0 – 2.2

- 集成拆成**一条主线加若干子条目**：从站、面板总线、关联都能各自添加、修改、删除。
- 移植了三套**面板协议**，面板的**指示灯**可以被驱动，**面板的码**会被学习。
- 被别的程序占用的串口会**直接拒绝**，因为字节会被瓜分。
- 从站的**轮询**做得公平了，不应答的从站会被跳过一会儿，而不是拖住整条总线。
